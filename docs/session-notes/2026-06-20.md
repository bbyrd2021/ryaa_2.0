### Token vs client-id (the thing that confused us mid-session)
- `GOOGLE_CLIENT_ID` (in `.env` / Railway) = the **app's** static identity; the server verifies tokens
  against it. `id_token` = a **per-login** JWT proving a specific user signed in, sent in the
  `Authorization: Bearer` header, expires ~1hr. They are NOT the same thing; the id_token is minted at
  sign-in (the Expo app will do this in Phase 6; the OAuth Playground does it for backend testing).
