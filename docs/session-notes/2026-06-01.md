### Frontend wired (no more mock) ✅
- **`frontend/src/App.tsx`** — `handleSend` now `fetch`es `POST /propose`; branches on status
  (`proposed` → summary bubble + Confirm/Cancel; `rejected` → reasons; `not_calendar` → message).
  **Confirm** → `POST /confirm` with the stashed event → shows `created` message. **Cancel** →
  clears it client-side, no call.
  - New state: `pending: EventDetails | null` (the browser holds the proposed event between the

  - TS types `EventDetails`/`ProposeResult`/`ScheduleResult` hand-mirror the Pydantic models —
    **must stay in sync if a backend model changes** (the one cost of two languages).

### Agent-loop plan (next big step) 📐
- Reread Anthropic's "Building Effective Agents." Current brain = a **workflow** (fixed
  propose→confirm path). Decided to evolve it into an **agent** = "an LLM using tools based on
  environmental feedback in a loop," acting as the middleman between the calendar **state** and
  the user.
- **Wrote the spec: `docs/specs/agent-loop.md`** (version-controlled). Decisions locked:
  - First behavior: **clarifying conversation** (agent asks a follow-up instead of guessing).
  - **Read access: yes** — a `list_events` tool so the agent sees the calendar (ground truth).
  - The yield: **confirm before each mutation.** The agent has **no write tool**; its only exit
    to scheduling is `propose_event`, which hands a proposal to the human. `create()`/`/confirm`
    stay unchanged. (This is the Anthropic-faithful answer: read tools run free, the consequential
    action gets a human checkpoint.)
- Key gap identified: the provider only speaks `complete()` + `structured()`. An agent loop needs
  a third verb — **tool-calling** — which means extending the neutral `Message` with optional
  `tool_calls`/`tool_call_id`. Reference: `patterns/3-tools.py`.
- **4-bite build order** (all in the spec): 1) provider `act()` verb + `Message` extension,
  2) `list_events` on the backend, 3) `ryaa/agent.py` loop (2 tools hardcoded, `MAX_ITERS` stop),
  4) wire into `propose()` + `api.py` + `App.tsx` (multi-turn: send the transcript; new `"reply"`
  status for clarifying questions).
