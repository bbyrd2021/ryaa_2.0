### Architecture locked (the load-bearing decisions)
- **Host: Railway** (deploys from the GitHub repo, one-click Postgres).
- **Identity ≠ data provider** — keep auth and "whose calendar/tasks/mail" independent. Provider-
  agnostic identity; **Sign in with Google** for v1 (Apple later — App Store will require it anyway).
- **One Google account powers calendar + tasks + mail — NO mix-matching, by design** (Brandon's call).
- **Three agnostic backends** behind Protocols: `CalendarBackend` (exists), `TasksBackend`,
  `MailBackend`. **Google-only implementations for v1** — agnostic by interface, Google by impl.
- **User's real Google account = source of truth, NO mirroring.** We store no events/tasks/emails.
- **Event provenance = `extendedProperties` tag on the Google event** (+ native created/updated),
  owned by the backend. → **Dropped** the earlier `EventStore`/`SqlEventStore`/provenance-table idea.
- **Todos = Google Tasks** (Brandon's insight — Google's tasks are the todo equivalent, same account).
  No `Todo` table; `TodoSkill` rewired off the `StubTodos` stub. *This closed the last open question.*
- **Email in v1, INCREMENTAL Gmail scope:** `calendar.events` + `tasks` granted at connect (both
  "sensitive"); Gmail requested only on first email use (inbox-read is the heavier "restricted" tier).
  **Mail send routes through the existing `propose → confirm`** human-in-the-loop (high-stakes).
- **Per-request, per-user Scheduler** (rebuild cost is microseconds vs the LLM call; caching has a
  DB-session-lifetime gotcha — skip until profiling says otherwise).
- **DB = exactly TWO tables** (Google holds the real data):
  - `User`: id (surrogate PK) · auth_provider · provider_subject · email · timezone · created_at
    (unique on auth_provider+provider_subject; **key on the provider `sub`, not email**).
  - `ProviderConnection`: id · user_id FK · provider · credentials (**encrypted** refresh token) ·
    scopes · created_at. (Separate table = adding Outlook later is new rows, no migration.)
- **Persistence:** SQLModel; SQLite local → Railway Postgres; `create_all()` on startup (Alembic later).
