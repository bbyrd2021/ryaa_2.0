## Phase 6 — the Expo client (the marathon)
### 6a — scaffold ✅ (commit 8f10d3d)
- `mobile/` Expo blank-typescript app. **Two painful setup gotchas** (now in memory [[expo-dev-setup]]):
  pin SDK to match the App Store's Expo Go (scaffold gave SDK 56; phone's Go only did **SDK 54** →
  `npm i expo@~54 && npx expo install --fix`); and force the Mac LAN IP
  (`REACT_NATIVE_PACKAGER_HOSTNAME=<ip> npx expo start -c`) or the phone can't fetch the bundle
  (default advertised `127.0.0.1`).

### 6b — Google sign-in ✅ (commits 37a32f9, f9018dc, 849a8d6, 8717c78)
- **Architecture: backend session tokens** (not client-side expo-auth-session, which fights Google's
  redirect rules in Expo Go). `ryaa/session.py` (PyJWT, `SESSION_SECRET`); `current_user` now verifies
  OUR session token. **Backend-owned OAuth web flow:** `GET /auth/google/start` → Google →
  `GET /auth/google/callback` (exchange code, mint session, deep-link back to the app with
  `?session_token=`). App (`App.tsx`): `expo-web-browser` `openAuthSessionAsync` → captures the token →
  `expo-secure-store`. `app.json` scheme `ryaa`. Registered the localhost + Railway callback URLs in
  Google Console.
- **The bug that ate ~an hour:** `_connect_with_code` had **`client_id`/`client_secret` SWAPPED** →
  Google `invalid_client` ("OAuth client not found"). I chased quotes / stale servers / Railway
  deploys / cred hashes for ages before finally READING the function — the swap was obvious on sight.
  Fix 849a8d6 (also fixed `conn.Credentials` → `conn.credentials`). **Lesson logged in
  [[brandon-debugging-style]]: read the suspect function FIRST; A/B-test a fix before claiming it.**
